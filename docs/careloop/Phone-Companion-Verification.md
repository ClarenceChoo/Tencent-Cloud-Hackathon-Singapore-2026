# Phone companion verification ledger

Status: **in development; the complete PRD is not accepted**. Updated 28 September 2026.

The native implementation is under `mobile/`. The original website remains the caregiver/owner dashboard. No native microphone, physical-phone, live-provider, notification-delivery or deployed-network performance claim is established by automated fixtures or Metro export.

## Evidence collected

- Backend: **142 tests pass in full on SQLite and isolated PostgreSQL 15.14** after the speaker-check addition. The original 60 tests remain included; protocol fixtures explicitly select their baseline companion and create logical reminder occurrences.
- Full-app integration: **30 component tests** mount the production native app with the real voice/reminder hooks and storage code while controlling OS/storage/API ports. They cover tap capture/read-back/confirmation, read-back stop ordering, revoked care hidden before failing notification cleanup, retry after API disconnection, pending microphone-dialog handoff, stop before external navigation, stale/out-of-order care responses, late speech, screen-reader activation/preference persistence, restored-identity cleanup, cold connection failures, serialized reconnect/revocation and warm recovery. The tests reproduced the prior concurrent read-back/stop and revoked-view retention defects before the fixes. These are app-component fixtures, not native rendering, real secure storage or physical-phone evidence.
- Accessibility implementation: screen-reader state selects tap mode, mid-recording gesture changes cancel without upload, initial-query races preserve newer accessibility events, and the user preference is stored separately.
