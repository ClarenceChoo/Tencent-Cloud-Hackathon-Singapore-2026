# Phone companion verification ledger

Status: **in development; the complete PRD is not accepted**. Updated 27 September 2026.

The native implementation is under `mobile/`. The original website remains the caregiver/owner dashboard. No native microphone, physical-phone, live-provider, notification-delivery or deployed-network performance claim is established by automated fixtures or Metro export.

## Evidence collected

- Backend: **128 tests pass in full on SQLite and isolated PostgreSQL 15.14** after notification lifecycle changes. The original 60 tests remain included; protocol fixtures explicitly select their baseline companion and create logical reminder occurrences.
- Full-app integration: **13 new component tests** mount the production native app with the real voice/reminder hooks and storage code while controlling OS/storage/API ports. They cover tap capture/read-back/confirmation, read-back stop ordering, revoked care hidden before failing notification cleanup, retry after API disconnection, pending microphone-dialog handoff, stop before external navigation, stale/out-of-order care responses, late speech, screen-reader activation/preference persistence and restored-identity cleanup. The tests reproduced the prior concurrent read-back/stop and revoked-view retention defects before the fixes. These are app-component fixtures, not native rendering, real secure storage or physical-phone evidence.
- Accessibility implementation: screen-reader state selects tap mode, mid-recording gesture changes cancel without upload, initial-query races preserve newer accessibility events, and the user preference is stored separately. Talk height can grow; rows/tabs wrap; clinical captions start at 18 logical units. Real largest-font layouts and VoiceOver/TalkBack flows remain unverified.
- Audio-lifecycle regressions execute the production React voice hook with mocked native adapters. They cover release during permission/prepare, setup/cleanup failure, background/blur, recorder pause, permission loss, installation changes, accidental clips, the recording ceiling, protected-state failure, ordered clips, stale/expired replies, late player callbacks and delayed reminder-start writes during handoff. Failed cleanup keeps admission closed with a Retry stop action. Separate HTTP adapter tests cover authenticated HEAD, bounded requests, streamed size limits, cancellation and stalled bodies. These are React/native-adapter fixtures, not native-phone execution.
- Backend HEAD fixtures verify device ownership/revocation, expiry, proposal/plan/support-status invalidation and both reminder routes. HEAD does not claim an audio download or prevent an unplayed occurrence from being explicitly rerouted. Firmware core host checks and all eight existing pendant transport harness tests pass at this checkpoint.
- Care-journey fixtures use actual encoded AAC transport and scripted speech to cover correction/confirmation, all four medication report states, reviewed medication explanations, external blood-pressure readings, preventive transitions, support acknowledgement/resolution, follow-up outcomes and reviewed summary omission/expiry/revocation. They check phone/dashboard provenance, restricted caregiver visibility and invalidation of already-generated status audio after a record update. Dashboard component tests cover source labels, separate dates/history and the explicitly selected companion. These are not live-provider or physical-phone results.
- Recovery fixtures cover late phone completion/interruption for both reminder types after expiry and route handoff. They verify start-authorization evidence, ownership, revocation, exact retries, terminal-state conflicts, no new playback and unchanged medication report state. Native unit tests cover lost upload receipts, care-refresh failure, stop during recovery, stale/expired read-backs, conditional secure-state updates, recovery independent of the pending queue and draining delayed acknowledgement writes before unpair.
- Reminder-hook fixtures cover denial (including offline), Android channel denial, native token refresh, out-of-order acquisition, pending permission dialogs, timeout/late callbacks, installation changes, late native scheduling, registration writes during pause, failed cleanup with outstanding work, background retention, tap-before-refresh ordering and persisted disabled status. Backend tests verify private registration readback, permission/route requirements, delayed requests after denial/quiescence and concurrent version compare-and-set on both databases. The dashboard separates registration from connection and local coverage. No live Expo/APNs/FCM request was used for these tests.
- Notification fixtures cover generic schedules, stable identities, separate notification evidence, permission denial, owner revocation, push deduplication, invalid tokens at ticket/receipt time, bounded retry, route cancellation and dashboard presence. Expo responses use HTTP mock transport; no real push was sent. Provider acceptance is never recorded as OS delivery or medication taken.
- Routing tests cover generation compare-and-set races, owner/CSRF/patient boundaries, pendant power-off acknowledgement, phone cleanup before switching (including revoked phones), no automatic selection, queued reroute with the same occurrence/dose and expiry, no replay after download/start/completion/interruption/unknown/failure, stale audio/context/ACK rejection, exact ACK retries and switch/plan changes during speech generation. Slow speech generation holds no write lock. Native operating-system behavior is not established by these server fixtures.
- Migration tests upgrade an actual populated pre-Alembic schema, preserve a note and bindings, select only a single unambiguous existing device, reject an incomplete schema, inject failure after DDL and verify transaction rollback, then recover. Populated reminder/check-in migration preserves IDs, audio, acknowledgements and playback history; old download uncertainty is conservatively retained. Downgrade refuses to discard multiple delivery attempts. Earlier identity downgrade preserves care and revokes phone credentials before losing the device-type field.
- Phone identity tests exercise exact enrollment retries, two concurrent registrations, simultaneous owner approvals, expiry, CSRF, caregiver/other-patient denial, credential/code separation, capability checks, TLS requirement, rate limits and revocation.
- Audio tests invoke installed FFmpeg/FFprobe to convert actual AAC in M4A into canonical PCM WAV. They reject malformed, mismatched, overlong and video input, and unavailable decoding. The speech provider inside these tests is explicitly a fixture.
- Fixture phone flow: encoded audio → shared worker → unsaved proposal → authenticated speech assets → explicit concurrent confirmation → one committed note → permitted caregiver visibility. Another caregiver does not see the unshared note. Recovery uses the original upload digest and installation-scoped idempotency key.
- Correction and cancellation invalidate the old proposal. Another phone, even bound to the same patient, cannot confirm that phone's proposal or use its context. Phone-only operations reject pendant credentials.
- Browser phone flow: **eight checks pass against the production dashboard bundle** in desktop Chrome 153.0.8010.54 on macOS/arm64 with Node 25.2.1. Three independent sessions verify real owner enrollment/selection, encoded AAC correction/confirmation, source labels, exact retry, private notes, recipient changes, grant revocation/regrant, server-invalidated sessions and phone revocation. The previously visible timeline is cleared on 401/403; temporary failures retain data with a connection warning. React regressions include delayed results after access loss and a new sign-in.

## External dependencies and known engineering work

- The host has Command Line Tools but no full Xcode or iOS Simulator tools. An isolated Android SDK/adb/emulator and JDK 17 are now installed under ignored `runtime/android-build/`; no system Java or global SDK setting was changed. Android Studio is not needed for the verified command-line build. Prebuild and Metro export alone remain insufficient evidence of native compilation.
- Test phones, signing/install route, reachable HTTPS service, live speech provider and push credentials have not been supplied/verified. Credentials belong in secret configuration, not this repository.
- Native build/toolchain work and remaining software integration can continue independently. Physical accessibility and on-device care journeys require the listed test phones and services.
- `npm audit` reports 10 moderate transitive native-tooling advisories rooted in `uuid <11.1.1` through `xcode`/Expo tooling (GHSA-w5hq-g745-h8pq). The app uses `expo-crypto` for credentials. Do not apply npm's suggested downgrade to Expo 46; resolve compatibility during release hardening. Existing dashboard dependencies also report advisories and need a scoped review before release.
- Automatic notifications contain only generic text. Foreground synchronization checks the current route, plan and occurrence before speech. The scheduling and push implementation has fixture evidence only; real background notification delivery remains unverified.
