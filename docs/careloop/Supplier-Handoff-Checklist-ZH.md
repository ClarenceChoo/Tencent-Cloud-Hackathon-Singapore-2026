# Parse 老年人语音挂绳／卡套：硬件打样与交付要求

软件端已提供设备绑定界面、每台设备独立的 NVS 配置文件、HTTPS 录音上传、WSS 心跳／指令、确认后保存和照护者看板刷新。请先提供准确板型、PSRAM 配置和接线表，我们再生成适配固件。默认固件引脚未分配，不能直接认定适用于贵方硬件。云端与真实样机的联合测试仍需完成。

每台样机使用独立的设备凭证，不能复制同一个 NVS 文件到多台设备；腾讯云账号密钥不写入设备。首次启动通过 `CareLoop-XXXX` 配网（该名称暂保留兼容），手机页面输入一次性配对码。新固件支持开机时持续按住说话键五秒、两次振动后松开，以重新配置 Wi-Fi；保留设备凭证和提醒记录。请在实物上验证该流程。

## 1. 项目与分工

我们计划制作一款供老年人佩戴的语音挂绳／卡套设备，先制作 **1–2 台功能样机**。正面可放交通卡或证件，背面容纳电子元件。用户按住实体按键说话，松开后上传录音，设备通过扬声器播放回复，并提供振动反馈。

**本次委托范围为硬件选型确认、组装、电源设计、外壳制作及硬件功能测试。ESP32 应用固件、手机／照护者网页、腾讯云后端、AI 和用药管理逻辑均由我们自行开发。** 不需要供应商开发完整软件平台或提供绑定供应商云服务的成品方案。

请提供用于证明硬件正常的基础测试程序、源码及烧录说明；这属于硬件交付验证，不涉及我们的产品业务逻辑。如果只能提供部分测试，请在报价中明确列出。

预期连接方式：麦克风 → ESP32-S3 录音 → Wi-Fi → 我们的后端 → 返回语音 → 扬声器播放。手机通过同一个后端查看数据。设备不需要运行大语言模型。

## 2. 参考硬件清单

以下是参考方案，请根据尺寸、电源及供应情况提出替代方案，任何替换须先确认。

| 部件 | 需求与待确认事项 |
|---|---|
| ESP32-S3 开发板／模块 | 提供准确型号、版本、Flash 和 PSRAM 容量；优先考虑带 8 MB PSRAM 的配置，保留 USB 数据烧录及恢复方式 |
| I²S 数字麦克风 | INMP441 或经确认的兼容替代；提供接口、电压、声孔朝向及左右声道选择方式 |
| I²S 音频功放 | MAX98357A 或替代；确认供电、增益、使能方式及扬声器匹配 |
| 微型扬声器 | 参考直径 15–20 mm、额定功率 1–2 W；最终尺寸、阻抗、功率与胸前佩戴时的清晰度需实际确认 |
| 实体按键 | 较大、易按、有触感；支持按住录音／松开结束；布局应避免与启动功能冲突 |
| 振动马达及驱动 | 扁平币式振动马达，配套驱动电路及必要保护；不能直接由 GPIO 带动马达 |
| 电池 | 参考 3.7 V、约 500 mAh 锂聚合物电池；请确认尺寸、保护、最大充放电参数及供应型号 |
| USB-C 充电及电源电路 | 需包含适当充电管理、保护、稳压及电源开关；若支持边充边用，须明确负载分配／电源路径设计 |
| 电量检测 | 提供电池电压检测或电量计接口；仅测电压时，不要求假装输出精确剩余百分比 |
| 外壳与挂绳 | 优先 3D 打印；预留声孔、USB、按键、维修及电池空间，配可脱开的安全挂绳；按实际卡片尺寸确认卡槽 |

500 mAh 是初始容量参考，**不作为全天续航承诺**。请提供实测条件和结果。TP4056 模块只是可选参考，不能替代完整电源设计确认。

## 3. 组装前请先确认

1. 完整 BOM、准确开发板型号／版本、可用引脚与 PSRAM 配置。
2. 接线表：每个器件端子对应的实际 GPIO、电源或地，并标明电压和控制极性。
3. 电源框图：USB、充电、电池保护、稳压、功放、马达及电源开关的连接关系。
4. 保留可用的 USB 数据烧录、启动／复位及刷机恢复入口。不能只保留充电口。
5. 外壳初稿与总体尺寸／重量估算；先验证麦克风、扬声器、电池、天线和卡片的布局，再固定外壳。
6. 所提供的测试源码、原理图／接线资料及可编辑外壳文件应允许我们用于本项目后续开发；请提前说明任何交付或使用限制。

我们尚未锁定开发板，因此目前没有指定实际 GPIO 编号。请勿仅按网上任意示例接线，需以最终选定板卡为准。

## 4. 样机交付资料

- 已组装、可运行基础测试的样机及充电／数据线要求说明。
- 最终 BOM 与实际接线表，包含电源参数、扬声器阻抗、马达驱动和电量检测方式。
- 自制电路的原理图；使用现成模块时，提供模块型号、接线图及相关资料。如制作 PCB，提供约定范围内的设计源文件及制造文件。
- 基础测试程序源码、依赖版本、编译／烧录步骤及恢复刷机方法。
- 3D 打印文件和可编辑外壳设计文件，并说明组装、拆卸与更换电池方法。
- 测试视频及数据：录音、播放、按键、振动、Wi-Fi、充电、电池与稳定性。

测试时请使用测试网络和虚构数据。我们会在收货后自行写入设备身份凭据和后端地址；不需要供应商持有我们的腾讯云主账号、AI 密钥或真实健康数据。

## 5. 硬件验收项目

| 项目 | 验收方式 |
|---|---|
| 二次开发 | 我们可以按说明重新编译、烧录并恢复设备 |
| 录音 | 胸前佩戴位置录制约 10 秒语音，导出后声音可辨认，时长／音调正确；插入卡片及穿戴时也要测试 |
| 播放 | 播放测试语音，确认在约定音量下清晰，外壳不产生明显共振；记录测试环境 |
| 按键与振动 | 按住／松开动作可被程序识别；振动反馈有效，录音时不持续振动 |
| 网络及供电 | 在约定 Wi-Fi 环境连接正常；播放和上传同时产生负载时，无异常复位或明显电压跌落 |
| 充电 | 电流与电池规格匹配；说明是否允许边充边用，记录温升测试条件与结果 |
| 功耗 | 分别记录联网待机、录音／上传、播放、振动时的电流，说明仪器和测量条件 |
| 外壳及卡片 | 端口、按键、声孔可用，电池不受挤压；插卡后测试读卡与无线连接，确认是否需要调整布局 |

云端语音识别、AI 回复、用药提醒和照护者看板由我们实现并另行验收，不要求供应商完成整套产品功能。
